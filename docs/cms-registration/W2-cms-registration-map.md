## 4. Priority brittleness and test seams

**OBSERVED hard-coded/reference dependencies.** Relative `Liberty Mutual Claims Office Matrix_08-29-19.xlsx` and `Liberty Mutual Medical Dedicated Supervisor Mapping 04-07-2025.xlsx` depend on working directory, not `__file__`; the first is preflight-checked, the second opened directly (CMS.py:40,1217,1295,2140). CEM checker workbook `FCM CEM Checher.xlsx` is instead relative to executable/script location and date-sheet dependent (CMS.py:1915-1965). Office parser uses *substring* office ID matches and can overwrite prior matches with a later block (CMS.py:801-826,840-850,863-891); claim office assumes fixed claim-number positions (CMS.py:183-187). Default market/name hardcodes Liberty (CMS.py:112-126,634-649), and even when mailing differs, the physical-address similarity alone governs update (CMS.py:1229-1248). Regex/city heuristic may misparse address (CMS.py:731-783,1497-1505); location selection accepts substring address or fuzzy match and first hit (CMS.py:660-680). Printed `updating via AHK` is stale: AHK calls are commented out (CMS.py:894-910,1243-1263). Fixed sleeps throughout the flow and absolute DOM XPaths plus indexed `udf_*`/`ctl00_*` IDs make timing/layout changes hazardous (CMS.py:981-1000,1141-1148,1315-1323,1524-1529,1740-1748,1806-1829). The code twice references `driver.switch_to.default_content` without calling it (CMS.py:1264,1372), risking retained iframe context before the next frame switch; other branches call it correctly (CMS.py:1442,1516). SP `fetchone()` chooses unranked first result, Unity compares assigned date but not type, CMS Select Case disabled, provider name truncated to four characters, employer checks global popup anchor count, attorney uses substring name and last result link, attachment first sender match, RRS only row 0 by claimant (CMS.py:125-129,2039-2086,1002-1140,1540-1558,1424-1440,1661-1674,1754-1772,1850-1862). Those are **INFERRED wrong-record risks**, not confirmed production incidents. In `search_address`, lack of a selected result or unknown contact is not fatal; several lookup helper bool returns and broad catches are ignored (CMS.py:643-687,1513,1906-1911).

**Pure/separable logic for synthetic unit tests:** column-name mapping/first-nonempty and precedence (currently nested under DB fetch; inject synthetic cursor or extract mapper), office number `[2:5]`, referral-type→inventory and activity mapping, string normalization/`SplitName`, address normalization/`split_address`/`splitMailingAdd` and city extraction, supervisor prefix+name matching (with synthetic rows), customer name sanitizer, attachment suffix construction, exact CEM name+claim/date-sheet matching (inject synthetic in-memory sheet and clock). Evidence: CMS.py:131-278,714-783,913-920,1300-1314,1327-1367,1412-1418,1497-1505,1698-1719,1765-1769,1927-1965. **No implemented employer-specific Bill-To rules exist to unit-test yet**; only hardcoded customer/address search (CMS.py:616-687,1485-1519).

**Injected fakes required:** Selenium IE/Chrome navigation, frame/window switching, `Select`, JS click/postback, account login, CMS search/tabs/save and Unity latest-case traversal; pyodbc cursor/connection; openpyxl workbook adapter; Tk notify callback; pywinauto UIA RRS controls and win32 Case Id prompt. Evidence: CMS.py:80-90,112-147,289-307,489-531,790-891,925-942,980-1000,1141-1903,1967-2125. Synthetic fakes can prove orchestration and failure propagation but **not** actual IE-mode/portal semantics or RRS-generated Outlook drafts (CMS.py:289-307,1845-1903; BRD11:23-50).
