## A. Employer identity and actual selection

- `AI/referral_schema.py:21-25,53-55,59-64,112-125,157-160`: the referral's **Customer Name** in Claimant Information is extracted under canonical **`Employer Name`**; `Company / Market` is a *different* field. The prompt forbids taking this identity from Special Instructions. `AI/source_evidence.py:30-50` independently reads the labeled source `Customer Name` into `Employer Name`, overwriting the model result in `AI/referral_schema.py:344-361`. `clean_value` at `AI/referral_schema.py:293-299` collapses whitespace and missing sentinels; it does **not** resolve corporate aliases, E-codes or the bill-to customer. `AI/referral_schema.py:364-373` applies special-instructions precedence to some other keys, not `Employer Name`. Reviewed fields can be edited before CMS (`Final Code/finalcode/orchestrator.py:84-99`). If a form has a different employer identity exclusively in Special Instructions, the current extraction contract intentionally does not use it as employer.
- `Final Code/finalcode/field_adapter.py:32-34,91-113`: `customer <- Employer Name`, with `Not found` turned into blank. `Final Code/finalcode/cms_inputs.py:5-13` passes this as the CMS `customer` search input, not the bill-to insurer or employer-contact label; `claimID`, `claimNumber`, `claimantFull`, `referralType` are its other inputs. `Final Code/finalcode/orchestrator.py:98-123`: after review/gate it calls CMS, requires nonblank resolved `response['customer']`, and **replaces** the adapter's customer with that result before SLB. Therefore the CMS stage is an *employer-name resolver* despite its `customer` terminology; it does not prove bill-to `C02283` and employer `E-code` are simultaneously validated.
- `Processes/Reopen-Check/Deploy-Ready/reopen_flow.py:8-16,49-56` passes `data['customer']` to `check_customer`, stops on empty/CEM, and returns the selected name. `src/fcm_intake/workflows/reopen_flow.py:12-22,34-37` invokes `src/fcm_intake/workflows/customer_checker.py:8-24,43-56`, a shared-session wrapper invoking legacy `ValidateCustomer`; the standalone Reopen-Check UI takes an operator `customer` (`Processes/Reopen-Check/Stand-Alone/desktop.py:21-22`), not necessarily AI. Reopen-Check's tire-case routing at `reopen_flow.py:24-37` checks customer-name substrings, not E-code/bill-to relationship.
- CMS matching (`src/fcm_intake/legacy/legacy_customerchecker.py:297-320,326-345,445-507,513-593,810-844,865-955`): a normalized-name **substring** keyword table maps Comcast/UPS/Goodyear to E05408/E00654/E11483. If mapped, search by E-code and return **first result whose Type contains `E`** (`:926-932`), without verifying returned name, returned code, or linking customer. If unmapped, search first one/two words, score Type-`E` rows by normalized token Jaccard (0.55), coverage (0.35), SequenceMatcher (0.10) plus small length/order tie-breaks and threshold `MIN_MATCH_SCORE = 0.62` (`:98,540-593,933-952`). `CORP_MAP` makes `COMPANY` and `CO` identical (`:331-335`), so name matching alone cannot distinguish the two Goodyear suffixes. For no/weak results, prompts allow an **operator-supplied name**, not a row/code verified by automation (`:667-758,919-955`). The comment-blocked confirmation at `:940-948` is not executed. This routine returns a **string**, not an E-code nor a click selecting a CMS record.
- Legacy intake parser `src/fcm_intake/legacy/legacy_fcm.py:1495-1506` reads `Customer Name:` and converts *exact* `ups` to `United Parcel Service`, exact `comcast` to `Comcast Cablevision`. This parser is distinct from Final Code AI extraction; `Processes/SubjectLineBuilder/Deploy-Ready/legacy_steps.py:823-830` calls Reopen-Check when `skip_cms=False`, otherwise trusts supplied `allData['customer']`. It writes RRS builder `tbCustomer = 'Liberty Mutual Commercial Market'` and `tbEmployer = allData['customer']` (`:843-858,908-914`), which separates bill-to display from employer text but **does not select an employer search row** here. Standalone manual SLB accepts independently typed `customer` (Employer/customer) and `market` (`Processes/SubjectLineBuilder/Deploy-Ready/manual_flow.py:6,28`; `rrs_ui.py:165-168` fills the two edits, preserving an already populated EDI field at `:158-163`). This manual route need not pass through CMS.
- Unity actually selects an employer **typeahead item** conditionally: `src/fcm_intake/legacy/legacy_unity.py:269-336` only enters the search if existing readonly value equals `Not Given / Not Applicable`; strips punctuation, rewrites a name containing `goodyear tire & rubber co` to exactly that phrase, but searches using **only its first four characters** (`:295-299`). On exactly one item it clicks `li[1]` (`:302-318`); on multiple it alerts for manual selection (`:306-307`); on zero it searches and may click `Not Given / Not Applicable` and alerts for manual selection (`:321-336`). The reviewed current SLB performs no separate code-based employer row selection in the inspected `legacy_steps.py`/`rrs_ui.py` employer writes.
