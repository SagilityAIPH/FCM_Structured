## R9 — Social Security Number

1. **STATUS: CONFLICTS.** The shared AI prompt explicitly preserves masked SSNs and the Final Code completeness gate requires a nonblank SSN, contrary to leaving the SSN blank on a **new iCase claimant** with partial/no SSN. Legacy Unity also clears a prefilled SSN whose first three characters equal the placeholder prefix **without checking new versus existing**, contrary to preserving an existing claimant's value. No source code found that *inserts* the prohibited full placeholder; the existing-value clearing is the significant active conflict.

2. **EVIDENCE:**
   - `AI/referral_schema.py:24,65,106-126,145-155` includes canonical `Social Security Number` in claimant information and requires it in the JSON; prompt says “Preserve masked SSNs when printed” and preserve SSN leading zeroes, use documented facts/`Not found` for missing. `AI/source_evidence.py:35-50` recovers the labeled SSN from source claimant section and overrides the model at `AI/referral_schema.py:355-361`. `AI/referral_schema.py:293-299` only stringifies whitespace/missing sentinels, not partial/full categorization. `:496-505,527-529` marks an absent SSN missing and gate Failed. `Final Code/finalcode/orchestrator.py:84-107` stops on failed gate **before CMS and SLB**. `AI/daily_output.py` workbook exports use canonical required keys (see `AI/referral_schema.py:59-77`); this is storage, not entry.
   - `Final Code/finalcode/field_adapter.py:35,91-94,113-114` maps canonical SSN to `claimantSSN` and trims/blank-converts `Not found`, without testing partial/full. `Final Code/finalcode/cms_inputs.py:11-13` deliberately supplies only `claimNumber`, `claimID`, `customer`, `claimantFull`, `referralType`: **no SSN to CMS**. `Processes/SubjectLineBuilder/Deploy-Ready/legacy_steps.py:1737-1739` contains a **commented-out** `tbSSN` assignment from `allData['claimantSSN']`; the current `rrs_ui.py:563-585` claimant details have no SSN field/write. Standalone SLB manual input at `manual_flow.py:5-25` and standalone Unity schema at `Processes/Unity/Stand-Alone/unity_model.py:26-35` do not include SSN.
   - `src/fcm_intake/legacy/legacy_fcm.py:1652-1653,3695` extracts the `Social Security Number:` line and carries it as `claimantSSN`, without partial/full handling. `src/fcm_intake/legacy/legacy_unity.py:542-547` reads the existing value of portal input ID `intake-claimant-social-security-number-ssn-input` and clears it **if its first three characters equal `999`**; it never writes `dataRef['claimantSSN']` there. This Unity intake screen is the only executable SSN target mutation located. It is a prefix check of the UI's value, not an assignment of the forbidden placeholder, not a check of the remaining digits, and not gated to new claimants. `src/fcm_intake/legacy/legacy_unity.py:408-465` shows the claimant search block commented out; `:579-590` fills claimant name only when empty, but does not decide new versus existing SSN policy.
   - `Processes/SubjectLineBuilder/Deploy-Ready/rrs_ui.py:494-520` searches RRS claimants by DOB/name plus claim, selects a result and tracks `edi_selected` (EDI source only when one row); `:158-163,563-577` retains prefilled Edit values after EDI selection. No returned `new_claimant`/existing-profile boolean, no SSN read, and no SSN preservation decision; no-result (`None`) is not proven new in CMS. `src/fcm_intake/legacy/legacy_reopencheck.py:423-540` CMS Claimant Profile query locates rows/cases by claim and optionally claimant name; `Processes/Reopen-Check/Deploy-Ready/reopen_flow.py:20-56` returns `cases` and customer, not a claimant-profile existence/SSN-status result. `src/fcm_intake/legacy/CMS.py:949-1000` uses a claim/claimant DB result to search CMS profiles; its result is not passed as an SSN-policy signal. CMS Customer Search uses employer/Claim ID/name, not claimant SSN (`reopen_flow.py:49-55`).
   - Searched `SSN`, `ssn`, `Social Security`, `social_security`, `claimantSSN`, forbidden placeholder with/without punctuation, `partial`, `XXX-XX-`, `***-**-`, Unity input IDs, tests/fixtures, and `iCase`/`icasemanager` throughout scoped source. No executable SSN placeholder assignment or partial/full classifier found. Source fixture SSN-like values exist in `src/fcm_intake/legacy/legacy_unity.py:1556`, `tests/unit/test_daily_output.py:19,53`, `tests/unit/test_source_evidence.py:46` (none reproduced here). The first is embedded in a legacy example block under `if __name__ == '__main__'` near `:1522-1624`; these are privacy-review candidates, not evidence of production SSN entry. `src/fcm_intake/legacy/legacy_fcm.py:1633-1634` transforms a *phone number*, not an SSN.

3. **INPUTS:** Canonical `Social Security Number` (source claimant label/model JSON) exists after extraction; `claimantSSN` exists in Final Code adapter and legacy parser, but no current SLB/CMS/Unity stage enters this value. Original text, filename and `Special Instructions` are present after capture; none is a reliable structured **iCase** flag (`Final Code/finalcode/rrs_capture.py:40-46,79-82`). RRS claimant search's row/source and existing prefilled fields become available during MID SLB lookup (`rrs_ui.py:494-520`); legacy Unity can read the live SSN input during Unity (`legacy_unity.py:544-547`). CMS Reopen-Check sees claim-associated cases, not a definitive new-profile decision or existing SSN. Thus *partialness* is testable from a reviewed SSN string, but no implementation does so; whether an existing claimant already has partial/full SSN is not known at FIRST/MID gate, and merely seeing a matching case is not a sufficient substitute. At the actual Unity field access, the current value is readable, but profile provenance/newness still is not explicitly determined.

4. **OWNER AND TIMING:** AI parser/review owns extracted field and pre-CMS completeness gate; RRS Subject Line Builder owns claimant lookup and RRS Create but its SSN writer is disabled; Unity legacy automation owns the currently executable SSN clear operation on the Unity intake form. FIRST after extraction can detect masked/partial or absent values (and avoid treating them as completeness failures only once rule applicability is determined); MID **after claimant lookup and before SLB/Create or Unity** must establish new vs existing, and LAST immediately before Unity form commit should preserve the prefilled existing value (`legacy_unity.py:542-547`). A violation plausibly warrants pause to avoid deleting an existing claimant's sensitive identifier or creating a profile with the wrong value; no owner authority chosen.

5. **DETERMINISTIC OR AI:** A reviewed SSN string can be checked by deterministic masking/length rules without logging digits; absence is deterministic. New-versus-existing requires a trustworthy CMS/RRS identity lookup rather than LLM inference from the document. Determining iCase provenance requires captured routing/source metadata or operator confirmation, not the exclusionary attachment-name predicate. AI is not needed to decide whether to preserve an existing field.

6. **VIOLATION BEHAVIOUR CANDIDATES:** Flag partial/no extracted SSN plus unknown provenance; pause before bot tries to enter/clear or creates new profile when claimant identity/source is uncertain; correct by leaving the **new-profile** SSN blank only after identity/provenance are confirmed, and never clearing an existing prefilled value automatically. These are candidates, not a selected authority.

7. **GAPS, RISKS AND OPEN QUESTIONS:** Confirm the authoritative source of an iCase flag and how RRS/Unity signals a newly created versus selected claimant profile; determine whether the matching RRS EDI record is the same claimant as a CMS profile. Confirm whether Final Code's mandatory SSN completeness rule should be conditional for applicable referrals (`AI/referral_schema.py:496-505`) so a blank does not stop before CMS. Clarify the legacy Unity clearing rule: it currently clears *any* displayed value beginning with `999` even for an existing profile (`legacy_unity.py:544-547`), and a masked display may conceal the actual underlying value. Confirm whether a non-iCase new claimant ever receives a nonblank SSN, and which form owns it; current SLB `tbSSN` line is disabled and Unity has no extracted-SSN writer. Require redaction of SSN values in Wizard UI, logs and audit, and review source fixtures separately without copying their digits.
