# CMS Registration

CMS case setup and RRS **Complete Registration** follow Unity case creation/assignment and a supervisor's assignment to a registration agent (BRD slides 101–123). This is sequential but **decoupled**: an operator starts a separate run per claim after the handoff, not an automatic continuation of Unity or Final Code's earlier CMS customer-search stage. Investigation and evidence: [`docs/cms-registration/INVESTIGATION.md`](../../docs/cms-registration/INVESTIGATION.md), with W1–W3 reports in that directory.

- [`Deploy-Ready/`](Deploy-Ready/) owns the immutable request/candidate/step contract, the injected stage controller and lazily loaded live adapter. It is a separate parallel workstream.
- [`Stand-Alone/`](Stand-Alone/) owns the offline fixtures/runner, attended pywebview bridge, React UI, tests and source-only packaging recipe. See its [README](Stand-Alone/README.md).

Registration's stored-procedure lookup explicitly uses the existing `FCM_RRS_DB_CONNECTION` by owner authorization, with no CMS-connection fallback. The live desktop defaults to stopping before CMS setup; see the stand-alone guidance for the preview boundary and restart requirements.

In an explicitly authorized full setup run, body-part selection now reuses the shared guarded IE-compatible selector for a unique exact available option and requires fresh readback before Save. Missing labels or remaining supported native-selection failures still pause for an actual CMS choice instead of guessing a mapping: select and verify the correct option without clicking Save, then confirm in the registration app. Decline, unsafe controls/targets or unverified selection stops the run. This source change is offline-tested, not live selection/persistence evidence; restart the source desktop to load it.

Claimant-tab navigation uses the shared owned-driver click and legacy readiness waits without changing claimant fields. Failures report the lookup, opening or readiness phase and exception type rather than a generic portal message; document readiness alone is not claimant identity verification. This source-only hardening has not been live-validated.

Case setup likewise uses shared owned-driver navigation/typing and an exact IE-compatible inventory selector with fresh readback required before Save. Existing referral-source/manual rules are unchanged. Case failures report the specific phase and exception type; source-only checks do not establish live portal persistence.

Supervisor assignment also uses shared owned-driver IE-safe clicks and reports safe failure phases. If it requests manual correction, Confirm does not fill/save the field: select and Save the correct supervisor in CMS first. Confirmation is accepted only after fresh nonblank field readback, matching the mapped name when available; unresolved fields stop the run. Existing different supervisors are not overwritten automatically. These are offline-verified source changes, not live persistence evidence.

Supervisor verification recognizes the verified CMS `Last, First` display versus the mapping's `First Last` form, normalizing whitespace/case while preserving every name component. It does not infer reversed unpunctuated names, omit initials/suffixes or use fuzzy matches. Readback uses a small parameterized read-only DOM value script; unreadable/blank fields and genuine mismatches still fail with value-free reasons. The patched reader/verifier passed a read-only check against the owner's paused field, but full assignment and persistence remain unverified. Restart the source desktop to load the fix; an already-pending run still uses its original code.

Customer setup now waits for the Customer tab, uses the shared owned-driver click and requires the actual employer/Bill To fields before checking them. It verifies the supplied employer, the existing Liberty Mutual Commercial Market Bill To guard and the controlled office-matrix mailing street. Company identity comes from the Bill To company-name field, not the separate Assign Primary Location action. Missing-employer and Bill To location lookups use verified input and a unique newly opened popup; ambiguous matches require correction rather than guessed assignments. A blank existing Bill To address triggers the mapped-location lookup, not automatic acceptance. An office number without a unique matrix match stops setup before employer lookup; correct the input/reference rather than guessing an office or confirming to bypass it.

Assign Employer opens a synchronous IE modal. If that opening click times out after the modal appears, the bot continues only after verifying one new owned IE8 modal, document readiness and the expected Name/Search controls, with ownership rechecked before input. It never clicks again to recover; missing, ambiguous or unverified dialogs still fail. This source-only recovery is offline-tested, not proof of live employer assignment.

Missing-employer lookup failures also report a value-free `selection/handoff` summary: opening outcome, result-count bucket, automatic/operator path, popup open/closed state after frame restoration, and pre/post label/relationship classifications. Operator acknowledgement does not prove selection, and a client-side relationship change does not prove persistence. Unreadable observations are explicitly unavailable and do not replace the original error or decide acceptance. These diagnostics do not repair an unapplied employer selection; restart the source desktop to load them for the next owner-authorized run.

Employer-lookup failures pause in the original failed context before frame restoration. A restoration-only failure also pauses before cleanup. Leave that prompt and browser open for inspection: acknowledgement always fails/stops the run, never corrects fields, retries assignments, saves, enters corrective confirmation or continues to Providers. If restoration also fails, both the original and secondary safe phase/type are retained. Earlier steps may already have changed CMS. Restart the source desktop for the next owner-authorized test; an existing run retains its original code. This diagnostic boundary does not repair the unknown original lookup cause.

Other Customer recovery is verification-only: Confirm does not navigate, correct, fill or save anything. Manually open Customer and correct the fields first; confirmation then restores the owned frame and freshly verifies the employer, Bill To and matrix street. If the assigned employer has a different but equivalent name, a separate **CMS Employer Equivalence** prompt displays both names and requires explicit same-employer approval for this run only. Generic confirmation alone is insufficient. Approval is bound to the unchanged expected input and actual selected employer name/ID; missing/placeholder identities, refusal or changes stop the run. Bill To company and mapped street checks still apply. Automatic matching remains exact, with no fuzzy matching or remembered aliases. Unreadable, blank, unapproved mismatched or unverified corrections stop before Providers and RRS completion. Safe diagnostics contain no portal values. Restart the source desktop to load this offline-tested change; the paused run retains its original code, and live behavior/persistence remain unverified. Employer primary-location/contact/add/CEM work (FCM-1.1-139) and employer-specific Bill To/C02283 policy (FCM-1.1-103) remain separate.

If native Customer-tab lookup raises `JavascriptException`, the same bounded wait can use a read-only IE8-compatible lookup for one exact visible/enabled Customer link. Ambiguous or unsafe targets still stop; the lookup itself does not click or submit anything. Existing click/settling and field verification remain. A subsequent matrix-resolution error is separate and still blocks employer assignment until the office reference resolves. This compatibility repair is offline-verified, not proof of corrected live navigation.

Claim and Customer office resolution share the legacy worksheet order: `Liberty and Middle Market` first, then `LM Physical Address`, then `Manual Tracking LM Claim Office`. The manual sheet matches the identifier before the first dash, not office-like digits in the address. Alternate-sheet addresses serve as both physical and mailing addresses, matching legacy behavior. Ambiguous or malformed matching records stop rather than selecting the first result or inventing an address. A primary-sheet miss alone does not mean the office is absent from the workbook.
