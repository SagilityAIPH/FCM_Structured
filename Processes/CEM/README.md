# CEM — Employer Request Add

Phase 1 is source-only: [`Deploy-Ready/`](Deploy-Ready/) contains the immutable contract, pure controller/rules, lazy Edge adapter, daily CEM workbook compatibility layer, and offline synthetic tests. **Phase 2a source is in [`Stand-Alone/`](Stand-Alone/): offline scenarios, operator-started desktop bridge/UI, and unexecuted EXE packaging recipe. No EXE build, integration, release or live validation exists yet.** The operator will start a separate app after CMS Customer Search stops; this module never automatically starts or chains to Final Code/CMS Registration.

Owner decisions (2026-10-30): v1 only creates **new employer requests**, not existing-employer linking or address add. UAT is the testing default; production requires an explicit environment and configured URLs (production URL is not supplied). The bot clicks Submit only after attended form review and a separate explicit confirmation; click is followed by request readback before logging. Completed means **request submitted**, not employer approved. Address placeholders default to disallowed pending BA FCM-1.1-128; opt in with `allow_placeholder_address=True` only with authorization. FCM-1.1-129 (continue before CMU approval) remains open.

Scope excludes CMS Customer Search, Unity, CMS case setup, RRS option 10/3, CMU approval and Outlook. The packaged EXE is phase 2b (not built yet). The legacy CEM file is a read-only behavior reference, **never imported** because its import creates Edge. Investigation: [`docs/cem/INVESTIGATION.md`](../../docs/cem/INVESTIGATION.md). No live portal, workbook, network or database was accessed in this phase.
