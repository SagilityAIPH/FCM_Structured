# CEM Deploy-Ready (Phase 1, source only)

Load the files by path from this hyphenated directory. `contract.CEMRequest` is frozen: employer name, **claim number**, distinct PDF **Claim ID**, claimant first/last names, optional address1/2, city/state/postal/country, referral number, local record ID. `CEMSettings` is frozen: `environment='uat'`, explicit `employer_search_url`, `employer_add_url`, `allow_placeholder_address=False`, **absolute** `cem_log_path`, optional Edge driver path, bounded timeout. URLs and credentials never live in the controller. Configure machine-local settings through the eventual app (`config/local_settings.ini`/environment variables), not source literals. Production requires `environment='production'` and explicit HTTPS URLs; no production endpoint is known.

`cem_flow.run(request, *, stages, settings, on_stage=None, on_step=None)` accepts `CEMStages` injected callables: `search_employer`, `find_existing_request`, `fill_form` (filled-field readback), `review`, `confirm_submit`, `submit`, `read_back_request`, `record`, `find_log_duplicate`. It is **not a Start button**: the future operator UI must open idle, guard concurrent/double Starts atomically and call `run` only on explicit Start. A live caller invokes `cem_steps.open_live_session(settings, driver_factory=..., review=..., confirm_submit=...)` only at Start, runs with `session.stages`, and closes it in `finally`.

| Stage | Gate |
| --- | --- |
| START | Required employer, claim number, Claim ID, claimant names; configured environment/URLs/log. |
| VERIFY_SOURCE | Full operator-confirmed address; missing/Unknown stops `address_required` unless explicit placeholder opt-in. External CMS-search evidence is **not yet handed off or verified**. |
| SEARCH | Positive completed no-results signal only. Exact employer stops `already_exists`; any populated nonexact results stop `ambiguous_employer`; empty/loading stops `search_unverified`. Log + portal duplicate lookup before form fill. |
| REVIEW | Read back employer name, fixed selected bill-to **Liberty Mutual Commercial Market / C02283**, and address; explicit operator review or `cancelled/operator_cancelled`. |
| SUBMIT | Separate irreversible confirmation or `cancelled/submit_declined`; repeat log + portal duplicate check immediately before **one** bot click. An uncertain/raised submit stops `submit_uncertain`, with no retry or log. |
| VERIFY_RECEIPT | Re-search for a **unique submitted** request with reference, employer and claim number. Missing/mismatched receipt is `failed/receipt_not_found`, never inferred from click. |
| TRACK | Only after receipt, append and read back compatibility workbook row. Failure is `failed/tracking_failed_after_submit` retaining `submitted` + reference and a **do-not-resubmit** warning. |

Every result contains `outcome`, `reason`, `stage`, completed `stages`, `steps`, `request_status` (`not_submitted/submitted/unknown`), `request_reference` (verified only), `tracking_status` (`not_attempted/written/existing/failed`), `cem_log_row`, `problems`, sanitized `error` (`stage/type/message` or null), and `warning`. Exceptions including SystemExit become `failed/exception` except an exception during the irreversible submit, which is `stopped/submit_uncertain`; KeyboardInterrupt propagates. Other reasons: `invalid_request`, `configuration_required`, `address_required`, `already_exists`, `ambiguous_employer`, `search_unverified`, `duplicate_request`, `form_not_verified`, `bill_to_unverified`, `operator_cancelled`, `submit_declined`, `submit_uncertain`, `receipt_not_found`, `tracking_failed_after_submit`, `exception`, `request_submitted`. `completed/request_submitted` is **not** CMU approval.

## CEM log compatibility and unresolved shared path

`cem_log.py` writes exactly `FCM CEM Checher.xlsx` with today's `MMDDYYYY` sheet (injectable datetime). Columns: **A Claimant, B Claim ID (legacy header, value is CLAIM NUMBER), C Status='Submitted', D Claim ID (PDF), E Employer, F Request Reference, G Submitted At, H Environment**. The deliberately retained B heading is required because `legacy_cem.ensure_headers` rewrites A:C to `Claimant | Claim ID | Status` whenever the old writer runs; renaming it `Claim Number` would be overwritten. `CMS.py:1915-1965` ignores headers/status, compares A claimant and B against the **claim number**, exact after strip/lower, today's sheet only; `cms_steps.py:815-842,916-936` delegates to that reader. The added D header disambiguates the PDF Claim ID. Existing legacy rows/headers remain intact and D:H are only appended; an existing A/B row without a matching verified reference blocks a new write rather than being mistaken for proof of submission. Text-only/formula rejection, sidecar locking during duplicate check/atomic replace, and readback are implemented. **Legacy writer and CMS reader do not participate in the lock**; concurrent old-writer saves can still race, so operational coordination/shared ledger migration remains necessary.

The new writer requires an explicit absolute `cem_log_path`; it never guesses a module/EXE folder. Configure the **same physical workbook path** that `CMS.get_excel_path()` uses for the separately packaged CMS Registration reader (beside its executable when frozen, beside `CMS.py` in source mode), or update that reader in a separately authorized integration phase. CMS Registration presently has **no configurable CEM path override**: setting this writer's path alone cannot force its consumer to the same workbook. Validate the shared path before production; do not edit CMS Registration here.

## Verification boundary

Run `.venv-bedrock/Scripts/python.exe -m unittest discover -s Processes/CEM/Deploy-Ready -p "test_*.py"` from repo root. All fixtures are synthetic and offline. `CMS.py` is **not imported** in tests (its Selenium/pyodbc/UI dependencies and possible side effects); its `claim_exists` A/B/date/strip/lower semantics are reproduced in `test_log.py`.

**All live selectors are UNVERIFIED:** legacy absolute search/form selectors, bill-to autocomplete selection (typed label is explicitly rejected: selected customer-code readback is not implemented), country/state dropdowns, guessed no-results and request-list signals/columns, optional address2, and guessed Submit control. `cem_steps` is a fail-closed adapter scaffold, **not a live-ready submission path**: its form readback intentionally leaves `bill_to_code` blank, so the controller stops at `bill_to_unverified` until a real selected-customer readback is implemented and validated in UAT. Confirm login/session/auth source, DOM readiness, real positive no-results signal, request duplicate identity and receipt status/reference, dropdown persistence, and policy/customer existence before any live run. No live browser/portal, network, CMS, RRS, CMU, workbook location or credentials have been verified. No Stand-Alone Start UI/build exists in Phase 1.
